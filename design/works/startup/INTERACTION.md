# 시그니처 인터랙션 — 살아 있는 해도

한 장의 해도(캔버스)가 히어로부터 "직접 해 보기"까지 고정된 채, 스크롤 단계에 따라 장면을 바꾼다.
사용자는 이야기의 주인공이 아니라 관찰자 → 마지막에 조작자가 된다 (concept story: 문제 → 통찰 → 해법 → 직접 확인).

## 이야기 구조 (peak–end)
| 단계 | id | 해도 상태 | 사용자가 느낄 것 |
|---|---|---|---|
| 히어로 | `hero` | 보트 6척이 수렴선을 따라 수거 중. 왼쪽은 종이 단. | "뭔가 실제로 움직인다" |
| 문제 | `problem` | 보트 기지 정박. 쓰레기가 해안에 닿아 쌓인다. HUD "해변 도착" 증가. | 긴장 (inciting) |
| 접근 | `approach` | 자홍 점선 수렴선이 그려지고 입자가 그 선으로 모인다. | 통찰 (peak 1) |
| 1 예보 | `how-1` | 조류 화살표 격자 + 수렴선의 +2h/+4h/+6h 위치. | 계산 가능하다 |
| 2 출항 | `how-2` | 보트가 기지에서 출발, 계획 경로 점선. | |
| 3 수거 | `how-3` | 카메라가 보트 한 척으로 다가감. 입구 폭만큼 입자가 사라지고 적재율이 오른다. | 만족 (peak 2) |
| 4 하역 | `how-4` | 기지로 카메라. 돌아오는 보트, 분류 막대가 채워진다. | |
| 직접 해 보기 | `try` | 전체 해역. 바람 조절, 바다 누르기, 보트 켜고 끄기. | 조작의 결말 (end) |

## 상태 기계
```
[loading] --chart ready--> [playing]
[loading] --2d context 없음 / 오류--> [fallback-image]
[playing] --탭 숨김 or 해도가 화면 밖--> [paused] --다시 보임--> [playing]
[playing|paused] --reduced motion--> [still]   (단계 바뀔 때마다 정지 장면 한 번 그림)
단계 전환: active step 이 바뀌면 카메라·모드 트윈(1100ms). 트윈 중 다른 단계로 바뀌면 현재 값에서 새 목표로 이어서 트윈 (끊김 없음).
```

## 조작 (직접 해 보기 단계 패널 안, 해도 위가 아님)
### 바람 방향 — 다이얼
- Trigger: 다이얼을 끌기(pointer), 화살표 키(±45°), Home=북서 기본값. 프리셋 버튼 8개는 두지 않고 다이얼 + 키보드로.
- Rules: 8방위로 스냅. 바람이 바뀌면 수렴선 목표 위치가 바뀌고, 선은 1.2초 동안 새 위치로 미끄러진다. 수거 중이던 보트는 가장 가까운 새 선 구간으로 경로를 다시 짠다.
- Feedback: 다이얼 바늘 회전, 라벨 "북서풍" 갱신, HUD 바람 값, 해도 위 수렴선 이동. 스크린리더: `role="slider"` + `aria-valuetext="북서풍"`, 변경 후 live region 에 "수렴선이 남동쪽으로 옮겨졌습니다" 한 번.
- Touch: 다이얼에만 `touch-action: none`. 해도 자체는 `touch-action: pan-y` 로 스크롤을 막지 않는다.

### 풍속 — 슬라이더
- 1–12 m/s, 기본 4. 높을수록 스티로폼(바람을 많이 받는 쓰레기)이 해안 쪽으로 빨리 밀린다. 10 m/s 이상이면 HUD 에 "보트 운용 한계에 가까움" 표시 (14 m/s 가 한계라는 제원과 연결).

### 바다 누르기
- Trigger: 해도의 물 위를 클릭/탭. 육지를 누르면 아무 일 없음 + 커서가 기본 화살표 (물 위에서는 십자).
- Rules: 누른 자리에 쓰레기 40개가 반경 30 안에 생긴다. 풀은 고정 크기라 가장 오래된 해변 쓰레기부터 재사용.
- Feedback: 누른 자리에 잉크 원이 퍼지며 사라짐(400ms). 보트가 가까우면 그쪽으로 경로를 바꾼다.
- 키보드 대안: 패널의 "쓰레기 흘려보내기" 버튼 = 남서쪽 바깥 바다에서 한 무리 유입.

### 보트 켜기/끄기 — 스위치
- `role="switch"`. 끄면 보트가 기지로 돌아가고 HUD 의 해변 도착 수가 빨리 오른다. 차이를 직접 보게 하는 비교 장치.

### 처음 상태로
- 바람·풍속·보트·입자를 초기값으로. 확인 대화상자 없음 (되돌려도 잃을 게 없다).

## 4단계 레일 (how it works 다이어그램)
- 해도 오른쪽 아래(모바일: 위) `<nav aria-label="작동 단계">` 의 `<ol>`. 각 항목은 해당 단계 패널로 가는 링크.
- 현재 단계는 `aria-current="step"`, 잉크 바탕. 지난 단계는 잉크 선, 다음 단계는 옅은 선.
- `how-*` 단계에서만 보이고, 그 밖에서는 숨김(`hidden` 이 아니라 `visibility` + `inert` 로 탭 이동에서 빠짐).

## HUD (해도 오른쪽 위)
- 시각(가속 시계), 물때(밀물/썰물), 바람, 운항 보트 수, 오늘 수거 kg, 해변 도착 개수.
- 계속 바뀌는 숫자라 `aria-hidden`. 의미 있는 변화만 live region 으로 알린다 (사용자 조작에 대한 결과만).

## 기타 마이크로인터랙션
- 채용: 행 버튼 → 펼침(높이 트윈 240ms, reduced motion 시 즉시). "이 자리에 지원하기" → 같은 자리에서 폼. 제출 → 검증 → 오류는 칸마다 / 성공은 폼 자리를 확인 상자로 교체하고 포커스 이동.
- 문의: 같은 방식. 문의 종류 라디오 기본값 "보트 운용 계약". 성공 상자에 "다른 문의 쓰기" 버튼.
- 두 폼 모두 실제로 아무것도 보내지 않는다. 성공 상자에 그 사실을 한 줄로 밝힌다.

## Reduced motion / 대체
- reduced motion: 입자를 단계별로 미리 시뮬레이션한 정지 장면. 카메라는 바로 목표 위치. 조작은 그대로 되고 결과도 정지 장면으로.
- 캔버스 실패/JS 없음: `img/chart-still.webp` (실제 렌더 캡처) 를 무대에 그대로 둔다. 단계 패널 글은 모두 HTML 이라 내용 손실 없음.
- `?capture`: 첫 장면을 시뮬레이션이 무르익은 상태로 바로 그린다 (썸네일·OG 촬영용).
