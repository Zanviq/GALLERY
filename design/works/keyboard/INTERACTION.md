# 가락 65 — interaction spec

Signature: **화면 속 키보드를 내 키보드로 친다.** 하나의 3D 보드가 페이지를 따라 네 자리(무대)를 옮겨 다닌다.

## 무대(slot)와 캔버스

WebGL 캔버스는 하나. 화면에 가장 많이 보이는 무대로 DOM 째로 옮겨 붙는다(스크롤과 같이 움직여 흔들림이 없다).
떠난 무대에는 마지막 프레임을 2D 캔버스로 남겨 두고, 시작할 때 모든 무대를 한 번씩 그려 둔다 → 빈 무대가 보이는 순간이 없다.

| 무대 | 카메라 | 움직임 |
|---|---|---|
| `main` (히어로 + 분해, sticky) | 3/4 앞-오른쪽 위 → 분해 시 옆 3/4 | 스크롤 진행도 p 로 분해/재조립 |
| `layers` (동작 줄이기 전용) | 분해 고정 시점 | 버튼으로 층 이동, 애니메이션 없음 |
| `color` | 낮은 3/4, 가까이 | 끌어서 돌리기, 아주 느린 턴테이블 |
| `typing` | 거의 위에서 | 타건 테스트 입력에 따라 눌림 |

## 키 누름 (trigger → rules → feedback)

- **Trigger**: window `keydown`/`keyup` (event.code 기준, 한/영 상태와 무관), 무대 위 pointer.
- **Rules**
  - `preventDefault` 를 절대 하지 않는다. Tab/Enter/Space/글자 입력은 원래대로 동작하고 보드는 '보여 주기만' 한다.
  - `event.repeat` 는 소리를 내지 않는다 (키는 계속 눌린 상태).
  - 매핑 없는 키(F1 등)는 무시. Escape·Backquote → Esc 키, AltRight·Lang1·HangulMode → 한/영, ControlRight·Lang2·HanjaMode → 한자, ContextMenu → Fn, Home·Insert → Del 자리.
  - `blur`, `visibilitychange` → 눌린 키 전부 놓기.
  - 터치: pointerdown 후 70ms 안에 8px 넘게 움직이거나 pointercancel(스크롤 시작) 이면 누르지 않는다. 그 전에 손을 떼면 짧게 눌렀다 놓는다. 마우스는 즉시.
  - 멀티터치: pointerId 별로 따로 누른다.
- **Feedback**
  - 키캡+스템이 스위치 이동 거리만큼 내려감: 누름 32ms(ease-out), 놓음 70–90ms(살짝 튀어오름). 택타일은 0.5mm 에서 한 번 멈칫, 클릭은 1.9mm 에서 툭.
  - 소리(켜져 있을 때만): 스위치별 합성음, 키 위치마다 음높이 ±4%, 큰 키(스페이스·시프트·엔터·백스페이스)는 낮고 길게 + 스태빌 덜컥.
  - 사양 섹션의 배열도에서 같은 키가 강조된다.
- **첫 등장**: 모델 준비 → 0.6s 동안 왼쪽→오른쪽 물결 눌림 한 번 (보드가 움직인다는 힌트). 동작 줄이기면 없음.
- **가만히 있을 때**: 히어로 흔들림·색 무대 턴테이블은 마지막 입력(포인터·키·스크롤) 10초 뒤 천천히 멈춘다. 다시 움직이면 이어진다.
- **스페이스**: 히어로에서 1.5초 안에 글자 키를 친 직후, 포커스가 컨트롤에 없을 때만 페이지 스크롤을 막는다. 처음 누르는 스페이스(스크롤하려는 키보드 사용자)는 그대로 스크롤된다.
- **안내**: 히어로 아래 '키보드의 아무 키나 눌러 보세요' (터치 기기: '화면 속 키를 눌러 보세요'). 처음 누르면 '좋아요. 소리도 켜 보세요' 로 한 번 바뀐다(소리 꺼져 있을 때만).

## 소리 토글

- 상태 2개: off(기본) / on. 페이지를 열 때마다 off — 자동 재생 없음.
- on: AudioContext 생성·resume(사용자 제스처 안), 확인음 한 번. aria-pressed=true, 라벨 '소리 켜짐'.
- '소리 들어 보기'(스위치 섹션)를 누르는 것도 명시적 동의 → 토글을 on 으로 바꾸고 샘플 재생.
- AudioContext 를 못 만들면 토글 숨김 대신 disabled + '이 브라우저에서는 소리를 낼 수 없어요'.

## 분해 (main 무대, 스크롤)

섹션 높이 420svh(데스크톱) / 380svh(모바일), 무대는 sticky 100svh. 진행도 p(0–1)는 목표값을 따라가며 보간(0.14/frame).

| p | 상태 |
|---|---|
| 0–0.08 | 히어로. 제목·안내가 위로 빠지며 사라짐 |
| 0.08–0.30 | 층이 위아래로 벌어짐(위층부터 차례로), 카메라가 옆 3/4 로 |
| 0.30–0.86 | 8단계. 단계마다 한 층이 활성: 지시선 라벨 진하게 + 왼쪽 설명. 다른 층 라벨은 번호+이름만 |
| 0.86–1 | 재조립, 카메라 복귀, '다시 한 덩어리.' |

- 이전/다음 버튼: 해당 단계 위치로 스크롤 (키보드 사용자용). 층 목록은 DOM 의 `<ol>` 이라 스크린리더가 전부 읽는다. 지시선 라벨은 aria-hidden.
- **동작 줄이기**: 섹션이 늘어나지 않는다. 히어로는 조립된 보드 고정(흔들림·자동 회전 없음). 아래 '구조' 블록에 `layers` 무대: 분해된 상태를 고정 시점으로 그리고, 이전/다음/층 버튼으로 활성 층만 바꾼다(즉시).

## 스위치 (radio 3개)

- 선택 → 보드 전체의 이동 거리·소리 프로파일 교체, 힘-거리 곡선이 240ms 동안 모양을 바꿈(동작 줄이기: 즉시), 예약 폼 기본값도 바뀜.
- '소리 들어 보기' → 8타 리듬 샘플. 곡선 위 점이 타마다 누름 곡선을 따라 내려갔다가 놓음 곡선으로 돌아옴. 재생 중 버튼은 '멈추기'.

## 색 구성 (radio 4개)

- 선택 → 3D 재질 색이 360ms 동안 보간, 키캡 각인 아틀라스 다시 그림, `--accent*` 변수 교체(색 전환 300ms), theme-color 갱신, 다른 무대 스냅샷 다시 그림.
- `color` 무대: 끌어서 좌우 회전(관성), 6px 미만 이동이면 키 누름으로 처리. 터치는 세로 스크롤을 막지 않는다 (touch-action: pan-y).

## 타건 테스트 (state machine)

```
[대기] --첫 입력--> [진행] --문장 끝까지 입력--> [완료]
[진행] --Esc 또는 '다시'--> [대기]
[완료] --'다시' / '다른 문장'--> [대기]
[대기|진행] --언어 바꿈(한글/English)--> [대기]
```

- 대기: 문장 표시, 입력칸 비어 있음, '입력을 시작하면 시간이 갑니다'.
- 진행: 글자마다 맞음(ink) / 틀림(error 바탕) / 아직(ink-2). 한글 조합 중인 마지막 글자는 판정 보류. 속도는 1초마다 갱신.
- 완료: 속도(한글 '타/분', English 'WPM'), 정확도, 걸린 시간 + **내 가락**: 키 사이 간격을 그린 리듬 띠. 'aria-live=polite' 로 결과 한 문장 읽어 줌.
- 붙여넣기는 입력칸 안에서만 막고 '붙여넣기는 세지 않습니다. 직접 쳐 주세요.' 안내. 1.5초 안에 끝나면(자동 입력) 속도를 재지 않고 '—'.
- 내 가락: 키 사이 간격을 막대 높이로, 틀린 타는 오류색.

## 예약 (state machine)

```
[작성] --제출, 오류 있음--> [작성+오류 표시, 첫 오류 칸에 포커스]
[작성] --제출, 정상--> [예약됨: 예약증]
[예약됨] --'다시 고르기'--> [작성 (이전 선택 유지)]
```

- 아무것도 전송하지 않는다. 예약 번호는 페이지에서 만든다. 예약증 상태는 localStorage(실패해도 동작)에 이메일 없이 저장.
- 베어본 선택 시 스위치 칸 비활성 + '베어본에는 스위치와 키캡이 없습니다'.

## 성능

- DPR 최대 2 (모바일 1.75). 필요할 때만 그린다: 키 애니메이션·스크롤 보간·색 보간·히어로 흔들림 중일 때만 rAF.
- 탭이 숨으면, 또는 활성 무대가 화면 밖이면 멈춤.
- WebGL 없음/컨텍스트 생성 실패 → 모든 무대에 `fallback.webp`, 키 누름은 배열도에서만 보임.
